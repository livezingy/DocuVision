## Epic: Artifact pack (Download ZIP)

### Motive

Pro already exports one format per click (JSON / CSV / Markdown / Word) and displays figure crops, but there is no way to take **tables as files + figure PNGs** in one download. Batch JSON/XLSX is structured aggregation only. Figures live on disk at `OUTPUT_DIR/{task_id}/figures/{id}.png` and are served inline.

### Scope (MVP)

- `GET /api/v1/tasks/{task_id}/export/zip` (add `zip` to the existing format enum).
- Optional `include=tables,figures,json` (default `tables,figures`).
- Server-side `zipfile` written to disk (not buffered entirely in RAM), then `FileResponse`.
- ZIP layout:

```
{task_id}_pack.zip
  manifest.json
  tables/tables.csv
  tables/tables.xlsx
  tables/table_{nn}_p{page}.csv
  figures/index.csv
  figures/{figure_id}.png
  figures/merged/{id}.png
```

- UI: one **ZIP** button in the right-panel `export-section` (same row as JSON / CSV / Markdown / Word).
- Reuse `ExportService.to_csv` / `to_excel` and existing figure files. Do not re-crop. Do not change `figure_step` contract.

### Out of scope

- Lite ZIP, Batch multi-task ZIP
- Table-region screenshots (no table crop pipeline today)
- Formula / seal images
- Embedding crops into DOCX/XLSX
- Client-side JSZip

### Acceptance

- **PACK-ZIP-001**: completed Pro task with tables + figure crops → `GET .../export/zip` returns 200, body starts with `PK`, namelist has `manifest.json`, `tables/`, `figures/`.
- Local mock: `backend/tests/test_pack_export_service.py` (no paddle).

### Adversarial check

- **Memory**: packing 200+ 2x-raster PNGs into an in-memory buffer can OOM. Builder must stream to a file with `ZIP_DEFLATED` and enforce `MAX_PACK_BYTES` (413 when exceeded).
- **Missing crops**: `enable_figure_export=false` or a failed crop must still produce a tables-only ZIP (`figure_count: 0`), not 500.
- **Restart**: single-task `tasks` dict is still in-memory (v1.5 out of scope). After restart the ZIP route 404s even if PNGs remain on disk.
- **Path traversal**: figure ids packed from disk must use the same `[A-Za-z0-9_-]+` rule as `GET .../figures/{figure_id}`.
