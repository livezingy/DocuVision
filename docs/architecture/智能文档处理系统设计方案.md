## 1. 系统目标

基于 PaddleX 套件，构建一套对标 Azure Document Intelligence 的智能文档处理系统，具备以下特征：

- **默认通用**：OCR 文本、版面解析、表格、图像区域提取开箱即用
- **按需增强**：公式识别、印章识别、证件/票据字段提取作为可选插件
- **数据分层**：原始数据、融合数据、展示数据三层独立保留
- **可扩展**：架构统一，印章/公式/证件等后续类型无需改动核心流程

## 2. 核心引擎选型

| 能力 | 引擎 | 默认/可选 |

## 3. 坐标系统设计

处理流程中存在两个关键坐标空间：

```
原图坐标空间 (original)
       ↓  预处理正变换（仅旋转纠偏，去扔曲已禁用）
预处理图坐标空间 (preprocessed)   ← PP-StructureV3 输入
```

> **当前实现（v0.9）：** `use_doc_unwarping` 在 `PPStructureV3._init_engine()` 中硬编码为 `False`。去扔曲路径已从代码中禁用，`coordinate_space` 始终为 `"original"`。

### 3.1 坐标模式（当前固定为 original）

`use_doc_unwarping` 在 `PPStructureV3._init_engine()` 中**硬编码为 `False`**，`coordinate_space` 始终为 `"original"`。后端根据此固定值写入 `preprocessing.coordinate_space`，前端直接读取：

| `use_doc_unwarping` | 坐标处理 | view 层坐标空间 | 前端展示图像 |
|---|---|---|---|
| `False`（**当前硬编码**） | 旋转逆矩阵 → 还原到原图 | `"original"` | `original_image`（原始上传图） |

前端叠加逻辑：
```
// coordinate_space 始终为 "original"
显示 original_image，polygon 直接叠加
```

### 3.2 use_doc_unwarping=False：旋转逆矩阵 → original 坐标

仅包含旋转纠正（0/90/180/270°）时，变换可精确求逆，view 层坐标还原到原图空间：

```python
import cv2
import numpy as np

def get_rotation_inverse_matrix(original_hw, angle):
    """
    给定原图 (h, w) 和旋转角度（0/90/180/270），返回逆变换 2×3 仿射矩阵。
    仅在 use_doc_unwarping=False 时可以精确还原到 original 坐标。
    """
    h, w = original_hw
    center = (w / 2, h / 2)
    mat = cv2.getRotationMatrix2D(center, angle, 1.0)
    cos = np.abs(mat[0, 0])
    sin = np.abs(mat[0, 1])
    new_w = int(h * sin + w * cos)
    new_h = int(h * cos + w * sin)
    mat[0, 2] += (new_w - w) / 2
    mat[1, 2] += (new_h - h) / 2
    inv_mat = cv2.invertAffineTransform(mat)
    return inv_mat, (new_w, new_h)

def apply_inverse_rotation(points, inv_mat):
    pts = np.array(points, dtype=np.float64)
    pts_h = np.hstack([pts, np.ones((len(pts), 1))])
    return (inv_mat @ pts_h.T).T.tolist()
```

`view_builder.py` 在构建 view 层时调用此函数，将 fused 层所有 block 的 polygon 坐标一次性转换到 original 空间。

### 3.3 use_doc_unwarping=True（已禁用，保留说明）

`DocUnwarping`（UVDoc）是深度神经网络，输出仅为像素结果（源码 `pipeline.py`：`item["doctr_img"]` 直接取像素），**无变换矩阵，无法精确求逆**。且实测会破坏 PP-StructureV3 内部 OCR 的文本行检测导致词粘连，当前已**永久禁用**。若未来需要启用，需同步解决文本质量问题。

### 3.4 预处理选项汇总

预处理由 `doc_preprocessor` 子 pipeline 提供，包含以下可选开关：

| 参数 | 可选值 | 坐标可逆性 | 说明 |
|---|---|---|---|
| `use_doc_preprocessor` | `True / False` | — | 总开关 |
| `use_doc_orientation_classify` | `True / False` | ✅ 精确可逆（仿射逆矩阵） | 旋转纠正，仅支持 0/90/180/270° |
| `use_doc_unwarping` | `True / False` | ❌ 不可逆（UVDoc 神经网络） | 透视/扔曲校正（**当前固定为 False，引擎 init 硬编码**） |

### 3.5 预处理模块输出

`coordinate_space` 由后端根据 `use_doc_unwarping` 自动写入，前端只读不写：

```json
// 当前唯一模式（use_doc_unwarping=false，引擎 init 硬编码）
"preprocessing": {
  "input_size": [4000, 3000],
  "output_size": [3000, 4000],
  "use_doc_orientation_classify": true,
  "use_doc_unwarping": false,
  "angle_deg": 90,
  "coordinate_space": "original"
}
```

## 4. 后端处理流水线

```
原始文档输入（PDF / JPG / PNG）
        │
        ▼
┌─────────────────┐
│   文档预处理     │  输出 preprocessed_image + 预处理参数（angle_deg 等）
│  use_doc_unwarping=False（硬编码）
└────────┬────────┘
         │
         ▼
    PP-StructureV3
    use_doc_unwarping=False（硬编码）
         │
         ▼
  按 block.type 分类（BLOCK_LABEL_MAP 白名单）
         │
         ├── vision_labels（table/image/chart/figure/flowchart）→ 直接保留
         ├── type = formula →  （可选）裁剪 → formula_recognition
         ├── type = seal    →  （可选）裁剪 → seal_recognition
         └── text 类（doc_title/paragraph_title/text/header/footer/footnote 等）
                   │
                   ▼
             block["content"] 经 _normalize_text() → element["text"]
             直接写入 fused 层（bbox 和 text 均来自 PP-StructureV3）
         │
         ▼
  全部 blocks 汇总，直接构建 view 层
         │
         ▼
  构建 view 层（use_doc_unwarping=False → 旋转逆矩阵 → original 坐标）
```

### 4.1 文本提取策略

**PP-StructureV3 `block["content"]` 字段直接用于所有文本类 block，无需 per-block OCR。**

- `block["content"]`：PP-StructureV3 内部 OCR 生成，包含段落级完整文本（正确词间空格），经 `_normalize_text()` 处理后直接写入 fused 层
- `block["text"]`：内部 OCR 行拼接，无词间空格（粘连），**不使用**
- 表格、图像类 block 直接使用 PP-StructureV3 结构化结果，不提取纯文本

### 4.2 预处理配置

PP-StructureV3 引擎在 `_init_engine()` 中使用以下固定 init 参数：

```python
init_params = {
    "use_doc_orientation_classify": True,
    "use_doc_unwarping": False,   # 永久禁用：UVDoc形变破坏内部OCR文本行检测导致词粘连
    "use_textdet_score_map": True,
}
```

外部预处理（`doc_preprocessor`）仅用于旋转纠偏，输出 `preprocessed_image`；PP-StructureV3 内部预处理关闭。

## 5. 文本提取规则

### 5.1 文本来源

PP-StructureV3 同时提供版面结构（bbox/polygon）和文本内容（`block["content"]`）。各 block 类型的文本处理方式如下：

| block.type | 分组 | 文本来源 | 显示 bbox | 处理方式 |
|---|---|---|---|---|
| `doc_title` / `paragraph_title` | doc_title_labels / paragraph_title_labels | `block["content"]` | PP-StructureV3 | `_normalize_text()` 规范化 |
| `text` / `abstract` / `content` / `reference` 等 | text_labels | `block["content"]` | PP-StructureV3 | `_normalize_text()` 规范化 |
| `header` / `footer` / `footnote` 等 | header_labels / footer_labels | `block["content"]` | PP-StructureV3 | `_normalize_text()` 规范化 |
| `figure_table_chart_title` / `aside_text` | vision_title_labels / unordered_labels | `block["content"]` | PP-StructureV3 | `_normalize_text()` 规范化 |
| `table` | vision_labels | tableV2 结构化结果 | PP-StructureV3 | cells/HTML/Markdown 直接使用 |
| `image` / `chart` / `figure` / `flowchart` | vision_labels | 无文本 | PP-StructureV3 | 仅保留区域 |
| `formula` / `inline_formula` | — | 无（Phase 1 跳过） | PP-StructureV3 | 可选 formula_recognition |
| `seal` | unordered_labels | 无（Phase 1 跳过） | PP-StructureV3 | 可选 seal_recognition |

> **v0.9 说明：** PP-StructureV3 `block["content"]` 在 `use_doc_unwarping=False`（硬编码）条件下包含正确的词间空格，直接使用。`block["text"]` 字段（内部 OCR 行拼接，无空格）**不使用**。

### 5.2 文本规范化

所有文本类 block 提取文本时调用 `_normalize_text(block["content"])`：
- 去除首尾空白、折叠内部多余空格
- 不做行间距推断或多行合并（PP-StructureV3 已做段落级别聚合）

### 5.3 processing_status 说明

fused 层各 block 的 `processing_status` 字段：

| block.type 分组 | processing_status | 说明 |
|---|---|---|
| 文本类（`_OCR_TEXT_LABELS`） | `"no_ocr"` | 直接使用 PP-StructureV3 content，无二次 OCR |
| 文本类（`_OCR_TEXT_LABELS`）且 `content` 为空 | `"no_ocr_empty"` | 文本块空内容兜底，不中断流水线 |
| table | `"skip_table"` | 保留结构化结果，不提取纯文本 |
| image / figure / chart | `"extracted"` | 写入裁剪图 URL |
| formula / seal | `"skip_formula"` / `"skip_seal"` | Phase 1 占位，不处理 |
| 未知/未注册类型 | `"passthrough_unknown_type"` | 透传并记录审计信息，避免隐式 `succeeded` |

### 6.5 三层差异对比与注意事项

#### 6.5.1 整体差异对比

| 维度 | raw 层 | fused 层 | view 层 |
|---|---|---|---|
| **受众** | 内部存储/重处理 | 调试/溯源 | 前端消费/用户下载 |
| **结构形态** | 两个引擎输出并排存储，格式各异 | 按 block 合并的统一结构，扁平列表 | 以消费者为中心重组，有文档级聚合数组 |
| **坐标空间** | preprocessed（引擎直接输出） | preprocessed（始终，与配置无关） | 始终 `original`（`use_doc_unwarping=False` 硬编码） |
| **text 类文本** | PP-StructureV3 `block["content"]` 原生输出（含词间空格） | PP-StructureV3 content 经 `_normalize_text()` 处理 | 同 fused，但去除了 provenance |
| **table/figure** | PP-StructureV3 原始结构 | payload 规范化 + `processing_status` | 同 fused payload，加 `crop_image_url` 等前端字段 |
| **融合决策信息** | 无 | `processing_status`（来源标记，文本类固定为 `"no_ocr"`） | 保留 `processing_status`，丢弃 `provenance` |
| **文档级聚合** | 无 | 无 | 有 `paragraphs[]`、`tables[]`、`figures[]`、`formulas[]`、`seals[]`、`fields{}` |
| **字段命名** | 引擎原生字段名 | `block_id`、`type`、`bbox_preprocessed`、`polygon_preprocessed` | `id`、`kind`、`polygon`（无 `_preprocessed` 后缀） |  
| **生命周期** | 调试模式下写盘；生产模式下仅内存中转 | 同 raw | 始终存在于 API 响应；生产唯一对外层 |

#### 6.5.2 view_builder.py 的职责边界

`view_builder.py` 是唯一在 fused → view 转换中做以下事情的地方：

1. **坐标变换**（唯一允许发生坐标转换的地方）：`USE_DOC_UNWARPING=False` 时调用 `apply_inverse_rotation()`，将所有 block 的 `polygon_preprocessed` 一次性转换为 original 坐标
2. **字段重命名**：`block_id`→`id`、`type`→`kind`、`polygon_preprocessed`→`polygon`、`width_preprocessed`→`width`
3. **丢弃调试信息**：`provenance`、`crop_offset`、`bbox_preprocessed` 不写入 view
4. **文档级聚合**：从 `pages[].elements` 聚合出 `tables[]`、`paragraphs[]`、`figures[]` 等跨页数组

**严禁在 fusion.py 或引擎适配层中做坐标变换**；fused 层的 `_preprocessed` 后缀字段名是对这一约束的显式提醒。

#### 6.5.3 各层注意事项

**raw 层：**
- `raw.pp_structure_v3` 保留 PP-StructureV3 的原生输出格式（不做任何规范化），供需要重新 fusion 时直接重放
- 生产模式下 raw 层**不持久化、不返回 API**；调试模式下写入 `backend/debug/{job_id}/raw_*.json`

**fused 层：**
- `bbox_preprocessed` 字段是 `[x_min, y_min, x_max, y_max]` 轴对齐矩形；`polygon_preprocessed` 是四点多边形，两者均来自 PP-StructureV3，**在任何配置下都不做逆变换**
- `provenance` 字段当前为**全 block 结构化记录**（包含 `primary_source`、`merge_strategy`、`status`、`block_type` 等），用于审计每个 block 的处理路径
- 新增引擎类型时，只扩展 `payload` schema，`block_id`/`type`/`bbox_preprocessed`/`polygon_preprocessed`/`processing_status`/`source`/`confidence`/`provenance` 八个公共字段**不允许改动**

**view 层：**
- `pages[].width` / `pages[].height` 的含义随 `coordinate_space` 变化：`"original"` 时为原图尺寸，`"preprocessed"` 时为预处理图尺寸；前端在渲染时需以此为归一化基准
- `polygon` 坐标为 8 个整数 `[x1,y1,x2,y2,x3,y3,x4,y4]`（四点顺时针），前端渲染框时直接连线
- `view.tables[]` / `view.paragraphs[]` 等文档级数组是 `pages[].elements` 的**引用投影**，不是独立副本；序列化时需注意避免出现既有 `elements` 又有重复数据的冗余

### 7.8 KIE 与 raw 返回策略（新增）

当 `enable_kie=true` 时，系统会按 `document_type` 触发 **`QwenDocumentKIEService`**（支持 `invoice` / `receipt` / `id_card` / `passport` / `bank_card`）。编排器在信封构建阶段将非空的 `kie_fields` 合并进 **`view.fields`**，并在 **`quality`** 中写入可观测字段。实现细节见 [kie.md](./kie.md)。

**文档级 KIE 实现要点（与代码一致）**

- **引擎**：**Qwen2.5-VL**（`transformers`），提示词与 JSON schema 来自 `kie_configs`。
- **输入**：以 **预处理页图**（或 PDF 首页栅格临时图）为 VL 输入；`kie_step` 传入的 `layout` / `table_meta` / `tables` 写入 `debug_input` 溯源，**不**作为 VL 推理必需条件。
- **任务结果中的中间字段**：`result.kie_fields`、`result.kie_meta`、`result.kie_input`（finalize 后 `view.fields` 与 `kie_fields` 应对齐；前端兼容仅含其一的 payload）。

**`quality` 中与 KIE 相关的字段**（成功路径示例，`kie_fields_count` 为 `view.fields` 中顶级键数量）：

```json
{
  "quality": {
    "kie_attempted": true,
    "kie_stage": "completed",
    "kie_error_code": "",
    "kie_fields_count": 3,
    "kie_items_count": 0,
    "kie_confidence_avg": 0.92,
    "kie_confidence_source": "uie-m-base",
    "kie_model_load_ms": 1200,
    "kie_items_source": "n/a"
  },
  "view": {
    "fields": {}
  }
}
```

字段说明：

| 字段 | 含义 |
|------|------|
| `kie_attempted` | 是否进入 KIE 分支（含跳过、失败） |
| `kie_stage` | `completed` / `skipped_doc_type` / `service_unavailable` / `runtime_error` 等 |
| `kie_error_code` | 与 `kie_stage` 对应的错误码，成功时为空字符串 |
| `kie_fields_count` | `view.fields` 字典键数量 |
| `kie_items_count` | 发票/收据场景下行项目数量（来自 `kie_meta`） |
| `kie_confidence_avg` | 字段级平均置信度（来自服务） |
| `kie_confidence_source` | 当前实现：尝试 KIE 时为固定串 `uie-m-base`，未尝试为空字符串（后续换引擎时可扩展） |
| `kie_model_load_ms` | Worker 加载 + 本次推理耗时（毫秒，来自服务 metadata） |
| `kie_items_source` | 明细行来源策略（如 `ItemsAggregator` 的 tier 说明），默认可能为 `n/a` |

**`kie_meta`（任务结果内，成功时）**：`attempted`、`succeeded`、`stage`、`error_code`、`error_message`、`confidence_avg`、`items_count`、`items_source`、`kie_model_load_ms`、`ocr_text_length`。

当 `document_type` 不在支持范围或服务不可用时，`kie_stage` 分别返回 `skipped_doc_type` 或 `service_unavailable`，并通过 `kie_error_code` 暴露原因。

`return_raw` 行为：
- `return_raw=true`：`/api/v1/jobs/{job_id}/result` 返回完整 Envelope（含 `raw`）。
- `return_raw=false`（默认）：结果中的 `raw` 统一返回空对象 `{}`，避免非调试数据外泄。

## 9. 前端展示规范

### 9.1 数据消费约定

- 前端默认只读 **view 层**，不直接消费 fused 或 raw
- 文本渲染：`view.pages[].elements[kind=text/title/paragraph].payload.text`
- 表格渲染：`view.pages[].elements[kind=table].payload.html` 或 `cells`
- 坐标渲染：`view.pages[].elements[].polygon`（坐标空间由 `preprocessing.coordinate_space` 决定；叠加到对应展示图像上，逻辑与坐标空间无关）
- 字段渲染：**以 `view.fields` 为规范数据源**（文档级 KIE）；任务轮询结果中若存在 **`result.kie_fields`**，与 `view.fields` 同源，前端实现可 **优先取 `kie_fields` 再回退 `view.fields`**（与当前 `frontend/app.js` 中 `pickKieFieldsMap` 一致）
- 展示元信息：可使用 `result.kie_meta`（如平均置信度、明细行数）

### 9.2 建议的前端 Tab 结构

| Tab | 数据来源 |
|---|---|
| Overview | `quality` + `preprocessing` |
| Text | `view.paragraphs` + `view.pages[].content` |
| Tables | `view.tables`（cells + HTML 预览 + 导出） |
| Figures | `view.figures` |
| Fields | `view.fields`（或任务结果中的 `kie_fields`，与前者同源） |
| Raw JSON | 完整 Envelope |

### 9.3 调试模式（服务级开关）

**调试模式使用服务级开关（config / 环境变量），而非每次请求参数。**

原因：
- 生产环境永远不应将 `raw`/`fused` 写盘，避免磁盘 I/O 和内部数据暴露
- 开发/测试环境希望每次请求自动落档，不依赖调用方主动声明
- 若允许请求级 `"debug": true`，会引入权限管理问题（任意调用者可获取内部中间数据）

**配置方式（`backend/config/settings.py` 或 `.env`）：**

```python
DEBUG_MODE = False            # 环境变量 APP_DEBUG_MODE 覆盖
DEBUG_OUTPUT_DIR = "backend/debug"
DEBUG_KEEP_LAST_N = 50        # 最多保留最近 50 个 job 的调试文件，超出自动清理
# USE_DOC_UNWARPING 不再作为运行时配置项；已在引擎 init 中硬编码为 False
```

**云端调试建议：**

- 仓库跟踪 `backend/.env.cloud` 作为非敏感模板（默认可设置 `OCR_LANG=en`）
- 运行 `backend/run.py` 时，若 `backend/.env` 不存在且 `backend/.env.cloud` 存在，启动脚本会自动复制模板为 `.env`
- 真实私密配置保持在本地 `.env`，不提交到仓库

**调试文件目录结构（`DEBUG_MODE=true` 时每个 job 自动生成）：**

```
backend/debug/
  {job_id}/
    original_image.jpg           # 原始上传图（始终保存，便于与 preprocessed 对比）
    preprocessed_image.jpg       # 送入引擎的图（始终保存）
    raw_pp_structure_v3.json     # PP-StructureV3 原始输出
    fused.json                   # fused 层完整数据
    quality.json                 # quality 层
```

> `view` 层不写入 debug 文件夹；它是用户可见层，由 API 响应返回。

**两种模式下的数据可见性：**

| 模式 | API 响应包含 | 磁盘写入 |
|---|---|---|
| 生产（`DEBUG_MODE=false`） | `view` + `quality` + `preprocessing` | 无 |
| 调试（`DEBUG_MODE=true`） | 同上，不额外暴露 raw/fused | `backend/debug/{job_id}/` |

调试数据通过独立端点访问，不混入正常响应：

```
GET /api/v1/jobs/{job_id}/debug
```

此端点仅在 `DEBUG_MODE=true` 时可用，否则返回 `404`。前端调试 Tab（Raw JSON）在生产模式下可隐藏或仅展示 view 层内容。

### 9.4 可视化与下载 JSON 一致性约定

**前端可视化与用户下载的 JSON 必须完全一致，通过架构强制保证，而非靠约定：**

- **view 层是唯一数据源**：前端渲染和 JSON 下载均读取同一 `view` 层，不允许前端自行从 `fused`/`raw` 合成展示数据
- **标准下载**：默认下载内容 = `analyzeResult.view` 序列化（Azure 风格，去掉 raw/fused）
- **调试下载**：完整 Envelope（raw + fused + view），供开发调试
- **坐标一致**：标注框 polygon 与 JSON 中 polygon 字段完全相同；坐标空间由 `preprocessing.coordinate_space` 标注，前端读取该字段决定展示哪张图

## 11. 关键设计原则汇总
 
| 原则 | 决策 |
|---|---|
| 文本提取 | PP-StructureV3 `block["content"]` 直接使用，无二次 OCR |
| 坐标来源 | 所有展示坐标来自 PP-StructureV3 |
| 坐标空间 | `use_doc_unwarping=False`（硬编码）→ 旋转逆矩阵 → `coordinate_space: "original"` 始终固定 |
| 段落 bbox | 始终用 PP-StructureV3 block bbox |
| 段落文本 | `block["content"]` 经 `_normalize_text()` 规范化，`processing_status: "no_ocr"` |
| 表格 | 完整保留 PP-StructureV3 结构化结果（cells/HTML/Markdown） |
| 表格策略 | 默认 `layout_first`；仅在 `table_allow_fullpage_fallback=true` 时允许整页 fallback |
| 状态兜底 | `processing_status` 对空文本与未知类型均有显式兜底（`no_ocr_empty` / `passthrough_unknown_type`） |
| 公式失败分级 | `formula_recognition` 输出 `error_level/error_code/failure_stage`，并写入 quality 便于回放定位 |
| KIE 闭环策略 | `enable_kie` 已进入流水线并调用 `QwenDocumentKIEService`（Qwen2.5-VL，按 `document_type` 路由），并写入 `view.fields` 与 `quality.kie_*`；详情见 [kie.md](./kie.md) |
| 印章失败分级 | `seal_recognition` 输出 `error_level/error_code/failure_stage`，并写入 quality 便于回放定位 |
| raw 返回策略 | `return_raw=false` 时统一返回 `raw={}`，`true` 时返回完整 raw 层 |
| 前端字段 | view 层字段即渲染字段；读取 `preprocessing.coordinate_space` 选择展示图像，坐标叠加逻辑统一 |
| 调试模式 | 服务级开关（`DEBUG_MODE` 环境变量），开启后自动写 `backend/debug/{job_id}/`，不混入 API 响应 |
| 兜底 | 文本 block 无 `content` 时写入空字符串，不中断流水线 |
| 扩展方式 | block 引擎注册表 + payload 多态 + 开关预留 |
