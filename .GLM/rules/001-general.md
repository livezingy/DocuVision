# 通用约束（GLM）

- 回复默认中文；代码、注释、docstring、日志、UI 文案、变量名一律英文。
- 结论先行；不谄媚；方案有问题直接指出。
- 遇模糊需求：先给最合理方案，再问要不要调整。

## 对抗性审查
- 交付前主动列出方案**何时不成立**（边界输入 / 规模上限 / 契约冲突）至少 1 条。
- 改契约或性能相关代码时，写明假设在什么条件下崩。

## 红线（auto-accept 下也必须先问）
- 删除文件/目录/git 历史（本轮明确授权除外）
- 修改 .env、密钥、token、CI/CD（.github/workflows/**）
- git push / rebase / reset --hard / 强推
- 安装全局依赖、公开发布

## 工程纪律
- 改完必须跑本地可跑的验证（见 003 测试分层），只改不验视为未完成。
- 不为跑通而注释报错或加绕过标记；找根因。
- 密钥不进代码、不进 commit、不进日志。
