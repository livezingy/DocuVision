## Motive：为什么是前端批次

v1.8.3 把 SPA 拆完（`frontend/app.js` 5708 → 172 行 / 33 模块 / 15 域），结构门禁 F1-F7 + C1-C9 + E1 已常驻 CI。
剩下的三件事都属于"结构已定、内容待收"，且都有明确的机检抓手：

1. **一个真实的前端行为缺陷**（P-007）：非 KIE 任务的结果面板显示 KIE 零值行 —— 已裁决走方案 B（纯前端）。
2. **拆分后暴露的巨函数**：F1 只约束**文件**行数（500），对**函数**长度无约束；最长模块
   `frontend/modules/pipeline/run.js` 现为 474 行，其中 `pollTaskStatus` / `startProcessing` 是主要贡献者。
3. **F6 的彻底解法**：F6 仍是名字级弱断言（deps 侧已由 C9 补齐），中间态 = JSDoc +
   `tsc --allowJs --checkJs --noEmit`，属评估项而非既定引入。

再加两个**已登记孤儿**（F7 只判可达性、不判接线）的 wire-or-retire 裁决 —— 它们的登记日期从 2026-09-17 起算，
A6 的 90 天告警会在 2026-12 前后提醒一次，本轮处理正好赶在告警之前。

### S1 · P-007：非 KIE 任务不再显示 KIE 元信息（方案 B，前端）

- 根因与证据见 [`PENDING.md`](../R&D/PENDING.md) P-007：后端 `api_models` 把 KIE 字段默认为
  `0` / `0.0` / `False` / `""`（未跑 KIE 也带零值）；前端 `frontend/modules/result-panels/quality.js`
  的 KIE 行**没有任何 gating**（`renderQualityPanelPro` 的 `summaryParts.push('KIE confidence…')` /
  `'KIE fields…'` 无条件执行——2026-09-20 读码修正：PENDING 原记的"条件是 `!= null`"实为无条件渲染）。
- **选定方案 B，判据分两段（2026-09-20 审核修正）**：
  - **summary 行**（`KIE confidence` / `KIE fields`）用 `quality.kie_confidence_source != ""` gate——
    该字段由 `document_pipeline_orchestrator.py:1077-1080` 保证只在 `attempted && succeeded` 时非空，
    语义即"真的量到过 confidence"。**不能只按 `kieAttempted` gate**：`skipped_doc_type` /
    `service_unavailable` / `runtime_error` 等失败路径同样是 `attempted=True`
    （`orchestrator:537/571/597/724`），只按它 gate 会留下失败态的 "0%" 误显（P-007 修一半）。
  - **KIE 警告块**（`kie_error_message` / `kie_production_reason`）按 `kieAttempted` gate——失败与
    跳过原因对用户有价值应显示；非 KIE 的 layout 任务不显示。
  - 不动 OpenAPI 契约，不做 `batch_export_service` CSV 列与 KIE 契约测试的连带改动。
- 必须同批补覆盖：vitest **4 态**（layout→无 KIE 行；completed→有；runtime_error→无 summary 行但有 ⚠；
  skipped_doc_type→无 summary 行但有 ⚠）+ e2e 1 例（backfill preset → 断言无 KIE 文本）。
  **e2e 需先扩 mock**：`mock-pro-api.js` 的 quality 现为 `{ kie_stage: 'skipped' }` 且无
  `table_backfill`，现有全部 e2e 里 quality 面板永远走隐藏路径（可见渲染路径 0 覆盖）——加
  `qualityPreset`（`backfill` / `kie_ok` / `kie_failed`），字段值用真实后端形态（`kie_stage` 用
  `""`/`"completed"`/`"runtime_error"`，不用后端从不产生的 `'skipped'`）。新增用例后
  **同 commit 把 `scripts/e2e_suite_pin.json` 14→15**（否则 E1 红——pin 机制首次真实生效）。
- 验收：layout 任务结果面板无 KIE 行；KIE 任务行为不变（confidence / fields / production hit 仍显示）；
  KIE 失败（runtime_error / skipped_doc_type）不再显示 "0%" 但仍显示原因。
- 落点：`frontend/modules/result-panels/quality.js`（D9，约 6 行 + 测试与 mock）。触及 UI → 交付说明里列云手测清单。

### S3 · JSDoc + `tsc --allowJs --checkJs --noEmit` 评估（结论性评估，不强制引入）

**结论（2026-09-20，实测后）：不引入。** 不作为 CI 门禁，本批次不新增 `typescript` 依赖，
不向生产代码加 JSDoc 类型契约。理由与证据见下。

- 目的：给"F6 名字级弱断言"找一个可维护的中间态（彻底解法需作用域分析）。
- **实测（tsc 5.6.3，`--allowJs --checkJs --noEmit`，不含 JSDoc，范围 = `app.js` + `modules/**` 33 文件）**：
  **272 个错误**，按成因分类后**没有一类是需要类型系统才能发现的新信号**：
  | 类别 | 数量 | 成因 | 性质 |
  |------|------|------|------|
  | TS2339 属性不存在 | 221 | ① legacy 跨模块 `window.*` 状态（`currentTableIndex` 19 / `batchState` 16 / `currentTables` 15 / `currentFigureIndex` 14 / `currentFigures` 12 / `viewingMergedIndex` 8 / `mergedFigures` 6 / `DOCUVISION_CONFIG` 6 / `pollInterval` 3 ≈ 99）② DOM 类型窄化（`value` 22 / `disabled` 20 / `checked` 15 / `style` 17 / `dataset` 10 / `files` 7 / 其他 ≈ 100） | 噪声：①L3 早已禁止**新**代码用 `window.*` 桥，收敛属结构问题；②`getElementById()` 返回 `HTMLElement`，每处需 `instanceof` 窄化或 `@type` 断言 |
  | TS2554 参数个数 | 39 | 注入依赖的零参占位 stub（如 `let updateEnhancementTabs = function () {};` 的调用点传 2 参） | 噪声：stub 签名是刻意占位；真正的不变量由 **C9** 守 |
  | TS2304 未声明名 | 4 | `DocuVisionExport`×2 / `DocuVisionDemo` / `DocuVisionUiFeatures` | 误报：`frontend/eslint.config.mjs:40-46` **有意**声明为 classic-script 全局 |
  | TS2345/2322/2552 | 8 | 杂项 | 噪声为主 |
- **受限范围对照**：只对 `modules/utils/**`（纯函数，排除 DOM/全局）跑同样配置 = **0 错误**
  → 该子集本就干净，且已被 vitest 覆盖，加类型检查无增量保护。
- **失败态③（"`deps` 里引用但未注入"）**：无 JSDoc 键表时 **tsc 完全无报**（实验：`initUntyped({delta})`
  而模块读 `deps.gamma` → 0 错误）；只有手工写 `@param {{alpha: () => void}}` 键表后才双向可捕获
  （实测 TS2741"模块默认值缺 `alpha`" + TS2353"调用点多 `beta`"）。**但维护键表 = 快照形态**，
  正是 P-008 gap 1 明确否决过的方案（"数据未更新时仍然全绿，恰是要防的失效形态"）；
  **C9 是零维护地从模块源码推导 `deps.*` 读取集合**，已关掉该 gap。
- **成本**：为达到可门禁状态需 ~250 处标注/窄化（≈100 处 DOM 窄化 + ≈99 处 `window.*` 声明），
  且是**长期**负担——每次新增 deps 注入或 DOM 访问都要维护类型契约，收益仅为抑制上述两类噪声。
- **替代路径（更便宜，均属独立决策）**：① 4 处 classic-script 全局用声明文件/JSDoc 消除误报；
  ② legacy `window.*` 状态的真正解法是逐批收敛进 `preview-state`（结构收敛，非类型问题）。
- **触发重估的条件**：出现"类型检查真实抓到产品 bug"的实例，或引入构建步骤 / TS 迁移；
  届时从 **`modules/utils/**`（当前 0 错误）** 起小范围开 `checkJs`，而不是全量接门禁。
- 说明：本项证据不改变行数预算的讨论（tsc 不是"比行数更好的质量代理"）——见 PENDING P-012。
