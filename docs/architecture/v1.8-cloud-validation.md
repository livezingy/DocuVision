## 0. 本次要验证什么（v1.8 改动 → 验证点映射）

| 改动 | 文件 | 验证点 | Gate |
|------|------|--------|------|
| 页级守门器 | `services/page_text_trust.py` | 真文本层判 `text_layer`、OCR 叠加层判 `overlay` | 标定 / TRUST-GATE-001 |
| 逐页化判定 | `services/file_type_detector.py` | 混合 PDF 逐页输出，不再 3 页独裁 | 阶段 A |
| 选择性回填 | `services/table_backfill.py` | 四层漏斗、provenance、计数自洽 | BACKFILL-001 |
| 契约统一 | `models/analyze_options.py` | 两路由参数一致 + `table_text_backfill` | 阶段 B |
| quality 摘要 | `orchestration/envelope_builder.py` | `quality.table_backfill` 字段完整 | BACKFILL-001 |
| Lite / core 退役 | `apps/lite/**`、`docuvision_core/**` | 删除后 import 不崩、既有功能不回退 | 阶段 A / G |
| 回滚开关 | `TABLE_TEXT_BACKFILL` | env 关断生效 | ROLLBACK-001 |

**已知风险（必读）**：PyMuPDF `get_texttrace()` 存在 C 层 refcount 缺陷，多页累积会**硬崩溃**解释器（`none_dealloc: deallocating None`），Python `try/except` 无法拦截。详见 [§6 GATEKEEPER-STABILITY](#6-阶段-f--gatekeeper-stability守门器稳定性)。

## 4. 阶段 C — 标定（§3.4 `page_type_probe`）

### 4.1 生成金样 fixture

```bash
cd <REPO_ROOT>
python scripts/trial/generate_trial_samples.py
# 输出 test_data/testfiles/trial/：
#   multi_column_techdoc / flowchart_page / architecture_diagram（既有）
#   bank_statement.pdf / symbol_grid.pdf（v1.8 新增）
```

> ⚠️ **两个必须注意的生成器行为**
>
> 1. **会重新生成全部 5 个 PDF**（覆盖既有 3 个）。脚本按 `FONT_CANDIDATES` 选字体：Linux 用 DejaVu Sans，**Windows 用 `seguisym.ttf`**。跨环境重跑会让既有 3 个 fixture 的**字节发生变化**（实测已触发），造成计划外 diff。
>    → **仅在云端（Linux / DejaVuSans）执行全量重生成**；若只需新增的两个，跑完后用 `git checkout -- test_data/testfiles/trial/{architecture_diagram,flowchart_page,multi_column_techdoc}.pdf` 还原既有三个。
> 2. 字体被**完整嵌入**，每个 fixture 约 1.35 MB（既有 3 个亦如此，属既有风格）。新增 2 个合计约 2.7 MB。

### 4.2 跑标定

```bash
cd backend
python -m app.services.page_type_probe \
  --input ../test_data/testfiles \
  --out ../outputs/page_type_calib.json
```

产出每页 `verdict` / `trusted` / `confidence` / `signals`（`invisible_ratio`、`image_coverage`、`font_count`、`glyphless_font`、`cid_rate`）。

### 4.3 本地实跑基线（Windows / PyMuPDF 1.27.2.3，第 1 页采样，供对照）

| Fixture | verdict | trusted | 说明 |
|---------|---------|---------|------|
| `GeneralFiles/bank_statement_sample.pdf` | text_layer | ✅ | 真文本层 |
| `GeneralFiles/financial_report_01/02.pdf` | text_layer | ✅ | 真文本层 |
| `GeneralFiles/transaction_ledger_unbordered.pdf` | text_layer | ✅ | 真文本层 |
| `PDF_Parsing/01_patent_us8582862b2_...pdf` | **overlay** | ❌ | invisible=1.0 / image=1.0，典型 OCR 叠加层 |
| `PDF_Parsing/02_datasheet_ti-lm358_1_23.pdf` | no_text | ❌ | 无文本层 |
| `invoices/invoice_sample_01.pdf` | no_text | ❌ | image_coverage≈0.89 |

> ⚠️ `GeneralFiles/financial_report_scansim.pdf` 名为 "scansim"，但实测为 **text_layer**（invisible=0、image=0），即它并非真扫描/OCR 叠加。人工标注时以**实际特征**为准，勿被文件名误导。

### 4.4 验收标准

1. 人工标注 27 个 PDF 的每页真实类型，与 probe 输出比对。
2. **假阳性率 `P(policy=用文本层 | 真实不可信) ≤ 1%`**（唯一灾难型错误）。
3. 真阴性偏高可接受（只损失速度，不损失正确性）。

### 4.5 人工抽查对齐产物

`DEBUG_MODE=true` 时回填会落 `backend/debug/backfill_alignment.json`，每候选 cell 一条：

```json
{"page":1,"table_id":"...","row":2,"col":2,"bbox":[80.0,160.0,180.0,208.0],
 "visual":"1,250.00","text_layer":"1,250.00","provenance":"text_confirmed"}
```

重点抽查：`bbox` 是否落在预期单元格内、`visual` vs `text_layer` 差异是否合理。

## 5. 阶段 D — BACKFILL-001（金样全管线，GPU 真跑 PP-StructureV3）

### 5.1 提交任务

```bash
cd <REPO_ROOT>
API="http://127.0.0.1:8000"

# 银行流水（千分位金额）
curl -s -X POST "$API/api/v1/documents:analyze" \
  -F "file=@test_data/testfiles/trial/bank_statement.pdf" \
  -F "enable_layout=1" -F "enable_table=1" \
  -F "table_text_backfill=auto" | tee bank_resp.json

# 符号表（✓ ⊗ ● ○）
curl -s -X POST "$API/api/v1/documents:analyze" \
  -F "file=@test_data/testfiles/trial/symbol_grid.pdf" \
  -F "enable_layout=1" -F "enable_table=1" \
  -F "table_text_backfill=auto" | tee sym_resp.json
```

### 5.2 轮询与取结果

```bash
JOB_ID=$(python -c "import json;print(json.load(open('bank_resp.json'))['job_id'])")
curl -s "$API/api/v1/jobs/$JOB_ID"                  # 等 status=succeeded/completed
curl -s "$API/api/v1/jobs/$JOB_ID/result" -o bank_result.json
```

### 5.3 验收解析

```bash
python - <<'PY'
import json
d = json.load(open('bank_result.json'))
bf = d.get('quality', {}).get('table_backfill', {})
print('table_backfill:', json.dumps(bf, ensure_ascii=False))

assert bf.get('enabled') is True, 'backfill not enabled'
assert bf.get('pages_text_layer_trusted', 0) >= 1, 'no trusted page'
c, cf, cb, cm = (bf.get('cells_candidates',0), bf.get('cells_confirmed',0),
                 bf.get('cells_backfilled',0), bf.get('cells_mismatch',0))
assert c == cf + cb + cm, f'counts inconsistent: {c} != {cf}+{cb}+{cm}'

for t in d.get('tables', []):
    prov = t.get('cell_provenance'); ocr = t.get('cell_ocr_text'); data = t.get('data')
    assert len(prov) == len(data), 'provenance grid misaligned with data'
    for i, row in enumerate(data):
        for j, cell in enumerate(row):
            if prov[i][j] == 'text_backfilled':
                assert ocr[i][j] is not None, 'backfilled cell must keep ocr_text'
            else:
                assert ocr[i][j] is None, 'ocr_text only for backfilled cells'
print('BACKFILL-001 structure: PASS')
PY
```

### 5.4 通过标准（BACKFILL-001）

| # | 判据 |
|---|------|
| 1 | `quality.table_backfill.enabled == true` |
| 2 | `pages_text_layer_trusted >= 1`（金样为真文本层） |
| 3 | `cells_candidates == confirmed + backfilled + mismatch`（计数自洽） |
| 4 | **银行流水**：金额/日期 cell 的 provenance 全为 `text_confirmed` 或 `text_backfilled`，且归一化后与文本层**逐字符相等** |
| 5 | **符号表**：符号 cell 字符 **100% 恢复**（`data` 中符号与文本层一致）；若视觉丢失则为 `text_backfilled` 且 `ocr_text` 保留原值 |
| 6 | `cell_ocr_text` **仅** backfilled cell 非 `None` |
| 7 | 金样输出相对 v1.7 基线的 diff **仅增量字段**（`cell_provenance`/`cell_ocr_text`/`quality.table_backfill`），无既有字段变更 |

## 7. 阶段 F — GATEKEEPER-STABILITY（守门器稳定性，**本次新增**）

针对 §0 的 PyMuPDF refcount 缺陷：

```bash
cd backend
python -m app.services.page_type_probe \
  --input ../test_data/testfiles/PDF_Parsing \
  --out ../outputs/stability_pdf_parsing.json; echo "exit=$?"
```

**通过标准**：`exit=0`，无 `Fatal Python error`。

**若崩溃**（退出码 `3221226505` / `0xC0000005`）：

1. 确认 PyMuPDF 版本（[§1.2](#12-依赖版本校验v18-新增必做)），先降级到 `<1.26.0` 重跑；
2. 仍崩溃则缩小范围分批跑（每次一个子目录），定位触发 PDF；
3. 记录到 [§10 结果记录](#10-结果记录)，并评估是否需要限制守门器单任务最大页数。

> 分析路径：`judge_page_trust` → `_trace_stats` → `get_texttrace()`。analyze 主链路**仅对有表格的页**调用守门器，风险低于遍历式标定；但多页且每页均有表格的 PDF 仍需实测。
