# DocuVision v1.5+ roadmap (living outline)

> Status: planning · complements [RELEASE_1.3.0_NOTES.md](../release/RELEASE_1.3.0_NOTES.md) and local Upwork R&D in `docs/R&D/upwork/`.

## Scope

Items deferred from v1.4 that unlock Upwork **T8–T10** and enterprise batch operations.

| Track | Capability | Upwork | Notes |
|-------|------------|--------|-------|
| **PDF toolbox** | merge / split / rotate / metadata | T8 | MVP stubs exist at `/api/v1/pdf-tools/*`; productize UI + audit log |
| **Searchable PDF** | OCR spans embedded as text layer | T10 / A | Independent of analyze Job; quality gate on multi-column PDFs |
| **Batch persistence** | SQLite/Redis queue, survive restart | D | Replace in-memory `batch_service`; optional Lite batch parity |
| **AcroForm fill** | CSV-driven form batch | T9 | PyMuPDF form APIs |
| **Mail bridge** | IMAP → DocuVision API | E | **Separate repo** (`docuvision-mail-bridge`); not in GPU `:8000` process |

## Non-goals (unchanged)

- Document translation, long-document VL QA, dedicated HWR mainline — see [docuvision-system-design.md §10](../architecture/docuvision-system-design.md).

## Suggested order

1. Batch persistence (unblocks production ETL demos)
2. PDF toolbox UI (quick wins on T8)
3. Searchable PDF quality pass (T10)
4. Mail bridge sample + n8n template (E class, external)

## Acceptance placeholders

- **BATCH-PERSIST-001**: create batch → restart server → batch state recoverable
- **PDF-SEARCH-001**: scan PDF → searchable PDF → pdfplumber text non-empty on born-digital path
- **PDF-TOOL-001**: merge 2 PDFs via UI → valid output download
